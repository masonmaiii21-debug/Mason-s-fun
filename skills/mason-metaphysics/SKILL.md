# 玄鉴 · 多模态命理综合分析

## 定位

本 Skill 将可程序化计算与传统文化解释分离：

- 八字/历法/择日基础数据：优先调用 `scripts/bazi-chart.cjs` 与 `scripts/almanac.cjs`。
- 紫微斗数：优先调用 `scripts/ziwei-chart.cjs`。
- 风水：按形势、朝向、建造/入伙时间、空间功能和流年信息分层分析。
- 面相/骨相外观/手相：先做可见特征观察，再做传统相术解释，不得把传统解释冒充科学事实。
- 综合判断：只做交叉印证，不强行让所有体系得出相同结论。

## 核心原则

1. **计算优先**：四柱、十神、藏干、紫微宫位/星曜、黄历宜忌等可计算信息必须以脚本结果为准，不凭语言模型手算。
2. **观察与解释分层**：照片分析先记录客观可见特征，再进入传统面相/手相解释。
3. **冲突不抹平**：八字、紫微、相术、风水出现冲突时，分别列出，不为了“看起来准”而强行统一。
4. **概率语言**：使用“倾向、可能、传统上常解释为”，禁止写成确定预言。
5. **不做高风险替代**：不得把命理/相术作为医疗、法律、投资、婚姻、升学、就业等重大决策的唯一依据。
6. **隐私最小化**：不收集身份证号、联系方式、精确住址等无关信息。
7. **传统文化定位**：明确说明命理、风水、面相、手相属于传统文化/民俗解释体系，并非经现代科学验证的预测方法。

## 视觉分析安全边界

### 面相

只允许描述图像中可直接观察的非敏感外观特征，例如：
- 面部轮廓、额部比例、下颌线、颧区外观
- 眉形、眼裂形态与相对间距
- 鼻部外观比例、唇形、耳廓可见轮廓
- 左右对称度、面部三庭五眼的近似比例

不得从照片推断或宣称：种族/民族、疾病或精神状态、智力、犯罪倾向、政治立场、宗教、性取向、真实人格、真实财富水平等敏感或无依据属性。

### 骨相

二维照片只能分析**外部骨性轮廓**，例如额部、颧区、下颌角、颏部、面中部比例。不得声称识别到真实颅骨结构、骨密度、骨龄或医学异常。若需要真正骨骼判断，应说明需要医学影像而不是普通照片。

### 手相

先观察：掌型、指长比例、拇指张角、主要掌纹的可见走向/连续性/深浅、掌丘外观。图像不清楚时必须降低置信度，不得“补画”或想象不存在的纹线。

## 工作流

### A. 八字/紫微/流年

收集：
- 公历或农历生日
- 出生时间（尽量到分钟）
- 性别
- 出生地（如要做真太阳时/时区边界校验）
- 目标年份或问题主题（事业/财运/感情/学业等）

优先执行：

```bash
node scripts/bazi-chart.cjs --solar 2000-08-16 --hour 10 --minute 30 --gender male
node scripts/ziwei-chart.cjs --solar 2000-08-16 --hour 10 --gender male --year 2027
```

如出生时间接近时辰边界，必须提示标准时间/真太阳时差异可能导致时柱或紫微时辰变化。

### B. 合婚/关系分析

分别计算双方八字与紫微，不直接用单一生肖或星座下结论。输出至少包含：
- 双方结构摘要
- 互补点
- 冲突点
- 沟通/价值观风险提示
- 传统命理层面的关系趋势
- 现实层面建议

禁止使用“天生绝配”“必离婚”等确定性断语。

### C. 风水

先判断资料完整度：
- 户型图/现场照片
- 房屋坐向或罗盘度数
- 建成/大装修/正式入伙时间
- 楼层与周边道路/建筑/水体
- 各房间用途

分析顺序：
1. 形势与空间动线（采光、通风、道路、门窗、遮挡等现实因素优先）
2. 坐向与八宅/玄空所需条件
3. 元运与流年
4. 房间功能匹配
5. 可执行调整方案

不得仅凭“某处放摆件”替代实际空间调整。

### D. 择日

先用 `scripts/almanac.cjs` 获取基础黄历信息，再结合具体事项与相关人的出生信息。不得仅凭“宜/忌”两个字做最终判断。

```bash
node scripts/almanac.cjs --date 2027-05-20
```

### E. 面相/骨相外观

需要照片时，优先：
- 正面自然光、无滤镜
- 头部保持水平
- 如需轮廓，再补左右 45° 或侧面照片

输出两层：
1. **可见特征观察**：只写照片中能看到的结构和比例。
2. **传统相术解释**：用“传统相术常解释为……”表述。

### F. 手相

建议同时提供左右手掌心高清照片。先判断：
- 是否完整显示手掌和指根
- 是否存在过曝/阴影/磨皮
- 主要纹线是否可辨

再分别记录生命线、智慧线、感情线、命运线（如可见），最后进入传统解释。

## 多体系交叉印证

详细规则见 `references/synthesis.md`。

默认将信息分成三种证据等级：
- **A 级：可计算结构**——历法、干支、宫位、星曜、日期等；只代表计算可靠，不代表预测科学有效。
- **B 级：可见视觉特征**——照片中可观察的外观或掌纹；受光线、角度、图像质量影响。
- **C 级：传统解释**——八字、紫微、风水、面相、手相的象征性含义；属于非科学验证的传统解释。

出现一致时：说明“多个传统体系在同一主题上出现一致指向”。
出现冲突时：说明冲突来源，并降低综合结论强度。

## 标准输出结构

1. **基础资料与数据质量**
2. **八字结构**
3. **紫微结构**
4. **当前大运/流年**
5. **面相/骨相外观观察**（有照片时）
6. **手相观察**（有照片时）
7. **风水/环境因素**（有资料时）
8. **多体系交叉印证**
9. **最值得关注的 3–5 个主题**
10. **现实可执行建议**
11. **不确定性与传统文化说明**

## 质量检查

完成前确认：
- [ ] 所有可计算数据是否来自脚本而非手算
- [ ] 是否区分了客观观察与传统解释
- [ ] 是否明确了照片质量/出生时间等不确定性
- [ ] 是否避免敏感属性推断和高风险决策替代
- [ ] 是否保留不同体系之间的冲突而非强行统一
